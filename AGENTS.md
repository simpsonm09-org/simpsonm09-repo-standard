# repo-standard working agreements

The reusable repository standard for the fleet. It owns the shared CI, linting, security, and governance.

## Ground rules

- The standard is consumed by other repositories. A change here reaches the whole fleet. Keep it backward compatible, or migrate the fleet in the same change.
- Operational scripts ship as a bash and a PowerShell twin with matching behavior and exit codes. Land a new flag or check in both in one change.
- Recipes stay thin and portable. No shell operators, `$VAR`, or Unix-only commands in a recipe.
- `ops.generated.just` is generated by `scripts/op.mjs`. Regenerate it, do not hand-edit it.
- No secret, credential, or machine path is committed.

## Commands

- `just lint`, `just check`, `just check-standard .`, `just check-repo .`, `just verify`.
- `node scripts/op.mjs render` regenerates `ops.generated.just` after an `ops.json` change.

## Repo facts

- Language and toolchain: Node for the runners, bash and PowerShell for the operational scripts, pinned in `mise.toml`.
- `ops.json` is the operation manifest. `scripts/op.mjs` dispatches it and renders `ops.generated.just`.
- `docs/` is the standard. `docs/adoption.md` is the entry point. `docs/root-readme.md`, `docs/documentation.md`, and `docs/license.md` define the repository conventions.
- `templates/` holds files copied into consuming repositories.
- `scripts/check-repo.mjs` checks this repository against the standard and applies the exception file. `scripts/check-standard.mjs` is the tree-local check it builds on.

## Skills

No repo-local skills. General best practices and integration come from the plugins.
